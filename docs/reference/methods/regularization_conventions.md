# Explicit regularization conventions

Potential-field inversions use physical_gradient by default. This retains the
current SimPEG definition, including physical derivatives, cell volumes and its
volume-normalized sensitivity weights. All existing defaults remain in place.

Individual scalar gravity and susceptibility inversions additionally accept
regularization_convention set to cell_difference. Supply four explicit
regularization_weights, reference/starting models and the other recipe choices.
Cartesian MVI and joint inversion do not implement this alternative convention.
It requires only the current inversion dependencies at runtime.

## Definition and reason

Earlier Sparse regularizers used dimensionless cell-difference stencils, face
length normalization and a different combination of sensitivity/volume weights.
Copying the same alpha numbers into a current physical-gradient regularizer
therefore does not establish the same objective, gradient or Hessian. On an
adaptive grid even a single global beta rescaling cannot remove all differences.

The alternative reproduces the scalar regularization definition in SimPEG
0.15.0. Active cells and faces are projected from the supplied mesh. Each raw
face difference is scaled by the minimum averaged cell width along its axis
divided by that face's averaged cell width. Sensitivity cell weights are the
normalized square root of the data-weighted Jacobian-column energy, with the
historical additive threshold. They replace the volume weight in this convention.
Custom positive cell weights multiply the sensitivity weights before face
averaging. IRLS face weights are applied after that averaging.
The stencil coefficients are dimensionless; the residual retains the model
property's units, rather than property units per metre.

For total-gradient IRLS, absolute cell-centered raw differences are summed
over axes and averaged back to each face. Thresholds retain the cell-difference
units and the historical face length normalization. Energy, gradient and Hessian
use the current full-quadratic normalization: twice the historical half quadratic,
consistently with the current data misfit.

This option specifies the regularizer, not the entire historical program.
Matching it does not reproduce an old optimizer's absolute CG stopping rule,
random state, complete IRLS schedule, regional preparation or export conventions.
Noise-weighted residuals, inner solver precision and spatial validation remain
separate checks. Cell selection, geometry, references and preprocessing still
have to be supplied explicitly.

## Independent evidence and regeneration

The test fixtures contain only deterministic synthetic grids and fields. Their
reference energies, gradients and Hessians were generated by the separate
SimPEG 0.15.0 / Discretize 0.7.0 environment, not by this implementation.
Tests cover uniform and nonuniform TensorMesh grids and a refined TreeMesh,
L2, frozen L1 and mixed sparse IRLS weights, including partial active-cell masks.

The current runtime needs no historical SDK to verify those fixtures. To
regenerate them, run scripts/generate_regularization_reference.py with --output
pointing to a new directory from a separately installed historical environment.
Keep that environment isolated from the current Core runtime. Its manifest
records library versions, source hashes and fixture hashes. No private datasets,
cached survey bytes or local project paths are part of this fixture corpus.
